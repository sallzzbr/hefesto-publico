# /spec

Use a skill `entregar` até o fim do planejamento (Step 4), **pulando o Step 3** (não pergunte
branch base — este fluxo não toca em branch), e carregue o template canônico de SPEC da skill
`dev-loop` (arquivo `spec-template.md` nas references dela).

Pedido inicial: $ARGUMENTS

Objetivo: produzir ou validar uma SPEC aprovada — critérios de aceite verificáveis, mapa
critério↔teste, non-goals, restrições, unidades paralelizáveis. NÃO iniciar implementação, NÃO
pedir opt-in multi-agente, NÃO criar branch. Pode registrar um perfil de execução sugerido para
uso futuro; a decisão de executar fica para uma chamada posterior.
